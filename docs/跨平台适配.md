# 跨平台适配说明（Windows · macOS · Linux）

> 适用版本：v1.1.0 · 最后更新：2026-11-15

GlassLyrics 原本是 Windows-only（依赖 WinRT SMTC）。v1.1 起引入**平台后端抽象层**，把「读媒体 / 控播放 / 探窗口」三件事拆成可替换的 OS 后端，主进程不再出现任何 `process.platform` 分支以外的东西。

**结论先给**：

| 能力 | Windows 10/11 | macOS 12+ | Linux（X11） | Linux（Wayland） |
|---|---|---|---|---|
| 读正在播放 / 进度 | ✅ WinRT SMTC | ✅ AppleScript（Music / Spotify） | ✅ MPRIS（playerctl） | ✅ MPRIS |
| 播放控制 | ✅ | ✅ | ✅ | ✅ |
| 跟随前台游戏窗口 | ✅ Win32 API | ✅ System Events（需辅助功能权限） | ✅ xdotool（X11） | ⬜ 无跨客户端窗口 API，自动退整屏 |
| 透明置顶窗 | ✅ | ✅ | ✅（需合成器） | 🟡 取决于桌面环境 |
| 全局热键 | ✅ | ✅ | ✅（X11） | 🟡 取决于桌面环境 |
| 托盘 | ✅ | ✅ | ✅（需 libappindicator） | ✅ |
| 开机自启 | ✅ | ✅ | ✅（XDG autostart） | ✅ |

## 二、每处改动的目的与关键实现要点

### 1. 平台路由：`app/backends/index.js`

**目的**：把「哪个可执行文件 + 哪些参数 + 哪个脚本」集中到一张表，主进程只拿结果。

**要点**

- 接口统一为 `{ cmd, args(script, extra), script }`：
  - Windows：`powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <script>`
  - macOS：`osascript -l JavaScript <script> [action]`
  - Linux：`bash <script> [action]`
- 附带 `capabilities` 能力表（透明度、置顶层级、热键、托盘、登录项、窗口探针类型），后续功能按能力降级，不再散落 `if (platform === ...)`。
- `trayIconName()`：Windows 用 `.ico`，macOS/Linux 用 `.png`（Linux 的 AppIndicator 不认 ico）。

### 2. 统一契约：`app/backends/parse.js`

**目的**：三端后端只需输出**同一种 JSON 行**，其余代码完全平台无关。

**要点**

- 媒体字段：`{ok, active, app, title, artist, album, status, statusValue, position, duration, hasCover, cover}`。
- `statusValue` 数字映射沿用 SMTC 语义（PLAYING=3 / PAUSED=2 / STOPPED=4 / NONE=-1），旧逻辑零改动即可复用。
- `cover` 兼容 `coverUrl`（macOS artworkUrl / Linux artUrl）。
- 窗口字段：`{ok, rect:[x,y,w,h], rectPhysical?, process, className, title, minimized, visible, desktop, error}`；Windows 的 `caption` 自动映射到 `title`。
- 降级状态（Wayland 无窗口 API）用 `ok:true + error` 表达，不抛异常、不阻断 UI。
- 动作别名：`playpause → toggle`。

### 3. Windows 后端（沿用，仅接入路由）

- 脚本不变：`smtc-bridge.ps1` / `smtc-control.ps1` / `window-probe.ps1`。
- 变化：由 `backendFor('win32')` 提供解释器与参数，避免命令拼接散落。
- 新增：媒体行错误（如脚本异常）只记录一次，防止每 500ms 刷屏。

### 4. macOS 后端（JXA）

**目的**：不引入任何第三方依赖，`osascript` 是系统自带。

**要点**

- `media-mac.js`：常驻进程，500ms 输出一行 JSON。优先取 `Spotify`，其次 `Music`；两者都在跑时取 `PLAYING` 的那个。
  - Music.app 的 `duration()` 单位是秒，Spotify 是毫秒 —— 后端内已归一为秒（>10000 视为毫秒）。
  - Spotify 的 `artworkUrl()` 作为 `coverUrl`；Music 无封面 URL，`hasCover:false`。
- `control-mac.js`：单次调用，按 `play/pause/toggle/next/prev` 派发 `play()/pause()/playpause()/nextTrack()/previousTrack()`。
- `window-mac.js`：`System Events → frontmost process → windows[0].position()/size()`。
- **权限**：读窗口需要「辅助功能」，控制音乐需要「自动化」。首次运行系统会弹窗；被拒后脚本返回 `accessibility-permission`，界面提示去「系统设置 → 隐私与安全性」授权。
- **Dock**：`app.dock.hide()`，覆盖层不占 Dock、不进 Cmd+Tab。

### 5. Linux 后端（MPRIS / X11）

**目的**：用 Linux 桌面事实标准的 MPRIS 协议，覆盖 Spotify、Chromium、VLC、mpv、Rhythmbox 等。

**要点**

- `media-linux.sh`：`playerctl metadata --format` 取字段（`|` 分隔），`awk` 把微秒转秒，`sed` 做 JSON 转义；无播放器时输出 `active:false`。
  - 缺少 `playerctl` 时输出 `{"ok":false,"error":"playerctl-missing"}`，主进程只记录一次并提示安装。
- `control-linux.sh`：`playerctl play|pause|play-pause|next|previous`。
- `window-linux.sh`：`xdotool getactivewindow` → `getwindowgeometry --shell`（X/Y/WIDTH/HEIGHT）→ `xprop` 取 `_NET_WM_PID`、`WM_CLASS`、`_NET_WM_NAME`，再从 `/proc/<pid>/comm` 取进程名。
  - `eval "$geom"` 只接受 xdotool 输出的纯整数赋值，无外部输入。
- **Wayland**：协议不提供跨客户端窗口几何，脚本检测 `XDG_SESSION_TYPE=wayland` 直接输出 `desktop:true + error`，覆盖层退回整屏显示，不报错、不阻塞。

### 6. 路径处理

- 一律 `path.join()` / `path.dirname()`，不用字符串拼 `/`。
- 打包资源根：`process.resourcesPath`（三端一致）；开发模式回落 `__dirname`。
- 后端脚本放在 `extraResources/backends/`，不走 asar（子进程需要真实文件路径）。
- 用户数据目录用 `app.getPath('userData')`：
  - Windows `%APPDATA%\glasslyrics`
  - macOS `~/Library/Application Support/glasslyrics`
  - Linux `~/.config/glasslyrics`
- Linux autostart 遵守 `XDG_CONFIG_HOME`（默认 `~/.config`）。

### 7. 文件系统与权限

| 事项 | 处理 |
|---|---|
| Linux `.sh` 可执行位 | 通过 `bash script.sh` 调用，不依赖 `+x`；同时 git 记录 100755 便于手动运行 |
| macOS 沙盒/公证 | 未签名分发（无 Apple 开发者证书），用户首次打开需右键「打开」或 `xattr -dr com.apple.quarantine` |
| Linux AppImage | 需要 `chmod +x` 后运行；部分发行版缺 FUSE，可用 `--appimage-extract-and-run` |
| 配置文件写入 | 统一 `fs.mkdirSync(recursive:true)` + 异常捕获，权限不足只记录不崩溃 |

### 8. 换行符（`.gitattributes`）

- 仓库内统一存 **LF**；`.ps1/.bat/.cmd` 检出为 **CRLF**（PowerShell 5.1 最稳），`.sh` 强制 **LF**（否则 `#!/usr/bin/env bash\r` 报 bad interpreter）。
- 二进制（png/ico/dmg/exe/AppImage/deb）标记 `binary`，禁止任何转换。
- CI 的 `check_compliance.mjs` 会检测 `.sh` 是否混入 CRLF 并失败。

### 9. 环境变量

| 变量 | 用途 |
|---|---|
| `ELECTRON_MIRROR` | 三端 CI 共用，避免从 GitHub 下载 Electron 超时 |
| `XDG_CONFIG_HOME` / `XDG_SESSION_TYPE` | Linux：autostart 路径 / 判断 Wayland |
| `DISPLAY` | Linux X11 必须存在，否则 xdotool 不可用 |
| `GL_FORCE_TRACK` / `GL_SMOKE` 等 | 测试钩子，三端通用（脚本路径不同，逻辑一致） |

### 10. 可执行文件与依赖

| 平台 | 运行时依赖 | 安装方式 |
|---|---|---|
| Windows | 无（Windows PowerShell 5.1 自带） | — |
| macOS | 无（`osascript` 自带） | — |
| Linux | `playerctl`、`xdotool`、`xprop` | `sudo apt install playerctl xdotool x11-utils` / `sudo dnf install playerctl xdotool xprop` / `sudo pacman -S playerctl xdotool xorg-xprop` |

> Linux 缺少依赖时程序不会崩：媒体区显示「未检测到播放器」，窗口自适应退回整屏，其余功能（歌词、外观、热键、托盘）正常。

### 11. 打包与 CI

- `app/package.json` 新增 `mac`（dmg + zip，x64/arm64）与 `linux`（AppImage + deb，x64）目标，图标统一 `assets/icon-512.png`。
- `build-all.yml`：
  - `verify` job（Windows）：合规 + 契约测试 + providers/lyrics + 三个 UI 回归（需要 Edge）。
  - `build` job（矩阵）：windows-latest / macos-latest / ubuntu-latest 各自 `electron-builder`，产物上传 artifact。
  - `release` job（tag 触发）：下载全部 artifact，一次性发布到同一个 Release，避免三端并发写冲突。
  - macOS 跳过签名：`CSC_IDENTITY_AUTO_DISCOVERY=false`。

## 三、如何验证三端均可运行

### 1. 通用（任何系统，无需 Electron）

```bash
node tools/check_compliance.mjs     # 文件齐全 / 无敏感文件 / 语法 / .sh 换行符
node tools/verify_backends.mjs      # 17 项：三端样本解析 + 路由 + 路径语义
node tools/verify_providers.mjs     # 36 项：六平台识别 / 歌词源顺序 / 解析
node tools/verify_lyrics.mjs        # 19 项：歌词引擎 / 缓存
```

### 2. Windows

```bash
cd app && npm ci && npm start
# 另一窗口
node tools/verify_menu.mjs && node tools/verify_autofit.mjs && node tools/verify_preview.mjs
# 冒烟（真实 WinRT）
GL_SMOKE=1 GL_FORCE_TRACK="孤勇者|陈奕迅|265" npx electron .
```

**期望**：`app-smoke.json` 里 `smtc.app` 为真实进程名，`hotkeys` 全绿，`autoFit` 捕捉到前台游戏。

### 3. macOS

```bash
cd app && npm ci && npm start
# 首次运行会弹两个权限请求：辅助功能（窗口）、自动化（控制 Music/Spotify）→ 全部允许
```

**手动验收**：

1. 打开 Apple Music 或 Spotify 放歌 → 主菜单「播放」页应显示曲名/歌手/进度，平台显示 `Apple Music` / `Spotify`。
2. 按 `Ctrl+Alt+B` 切布局 → 有反应说明全局热键生效。
3. 打开任意游戏（或无边框全屏的视频）→ 歌词应贴合窗口；若整屏，检查辅助功能权限。
4. 点「上一首 / 暂停」→ 音乐客户端响应（自动化权限）。
5. 主菜单「通用」页勾选开机自启 → `~/Library/LaunchAgents` 或系统「登录项」出现 GlassLyrics。

### 4. Linux（X11）

```bash
sudo apt install playerctl xdotool x11-utils   # Debian/Ubuntu
cd app && npm ci && npm start
```

**手动验收**：

1. `playerctl status` 有输出 → 启动后主菜单应显示曲目。
2. `xdotool getactivewindow` 有输出 → 切到游戏窗口应触发自适应（否则检查 `DISPLAY`）。
3. 托盘图标出现（GNOME 需 AppIndicator 扩展）。
4. `cat ~/.config/autostart/glasslyrics.desktop` 验证开机自启写入。

### 5. CI（无真机也能验证构建）

推送 tag 后看 Actions：`verify` 全绿 + 三个 `build` job 各产出安装包 + `release` 汇总。这能证明**代码在三端都能构建**，但不等于真机功能已验证（见下节限制）。

**v1.1.1 实测结果（2026-11-15，GitHub Actions）**：

| Job | 结果 | 产物 |
|---|---|---|
| verify（Windows） | ✅ 通过 | 合规 + 17 项契约 + 36 项 providers + 19 项 lyrics + 126 项 UI 回归 |
| build (windows-latest) | ✅ 通过 | `GlassLyrics Setup 1.1.1.exe`、`GlassLyrics-Portable.exe` |
| build (macos-latest) | ✅ 通过 | `GlassLyrics-1.1.1-arm64.dmg` / `-x64.dmg` + zip |
| build (ubuntu-latest) | ✅ 通过 | `GlassLyrics-1.1.1.AppImage`、`glasslyrics_1.1.1_amd64.deb` |

> CI 过程中实际踩到并修掉的三类「平台差异坑」，也是本地开发容易忽略的：
> 1. 回归脚本把 `C:/Users/<用户名>` 写死 → CI 无此路径，UI 回归全挂（改为 `os.tmpdir()`）；
> 2. `.deb` 强制要求 `author.email` / `maintainer` → 只在 Linux 打包阶段暴露；
> 3. `.deb` 强制要求 `homepage` → AppImage 能过、deb 挂，属 FPM 特有校验。

## 四、各平台限制与注意事项

### Windows

- 独占全屏（Exclusive Fullscreen）下任何置顶窗都不可见 → 用无边框全屏。
- 部分游戏反作弊可能拦截覆盖层，风险自负。
- 托盘图标必须是 `.ico`，`.png` 会显示空白。

### macOS

- **必须授权**：辅助功能（读窗口）+ 自动化（控制音乐）。被拒后功能静默降级，需手动去「系统设置 → 隐私与安全性」重新勾选。
- **未签名/未公证**：首次打开需右键「打开」，或 `xattr -dr com.apple.quarantine /Applications/GlassLyrics.app`。Gatekeeper 在 macOS 15+ 更严格。
- Apple Music 只有 AppleScript 接口，**没有逐字歌词、没有封面 URL**（`hasCover:false`）。
- 全屏游戏（尤其是 Metal 独占全屏）会盖住置顶窗；macOS 上没有 Windows 那种 `screen-saver` 层级的绝对置顶，建议「无边框窗口」模式。
- 点击穿透依赖 Electron `setIgnoreMouseEvents`，与 Windows 行为一致，但「跟随窗口」的坐标系以主屏左上角为原点，多显示器且排列在左侧时可能出现负坐标，已在 clamp 逻辑中处理。

### Linux

- **Wayland 是硬限制**：协议不允许普通应用读取其它窗口的几何。程序会自动退回整屏显示，无法"贴合游戏窗口"。需要贴合请登录 X11 会话（GNOME/KDE 登录界面可选 "Xorg"）。
- 透明与置顶依赖**合成器**（picom / KWin / Mutter 默认开启）。无合成器的裸 WM 下窗口会是黑底。
- 托盘需要 AppIndicator 支持（GNOME 需安装 `gnome-shell-extension-appindicator`）。
- 全局热键在 Wayland 下可能无效（compositor 决定），X11 正常。
- 部分发行版 `playerctl` 需要额外的 MPRIS 插件；Chromium 系浏览器播放网页音乐也能被识别（playerName 为 `chromium`/`firefox`，平台显示「其它播放器」，歌词走同曲匹配）。
- AppImage 若提示 FUSE 错误：`./GlassLyrics-*.AppImage --appimage-extract-and-run`。

### 三端共性

- **未在真机验证的部分**：本次适配在 Windows 上完成并全部回归通过；macOS / Linux 后端通过**契约测试 + CI 构建**验证，尚未在真机跑过完整交互（受开发环境限制）。首次在 mac/Linux 使用若遇异常，请附 `npm start` 控制台输出提 issue。
- 歌词接口与平台无关（HTTP），三端一致；缓存目录随 `userData` 走。
- 播放控制语义统一为 `play / pause / toggle / next / prev`，三端行为一致。
