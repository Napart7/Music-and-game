# GlassLyrics 技术方案（定稿）

版本：v1.1 · 2026-11-15（P0 通过后路线变更）

## 0. 一句话结论

用**一个独立的透明置顶窗口**复刻 DangoMusic 的视觉，跟随 QQ 音乐 / 网易云的播放状态显示逐字歌词。全程不碰游戏进程，因此不触发反作弊。

**SMTC 是什么（大白话）**：Windows 自带的「谁在放歌」公告板。音乐软件把歌名、歌手、封面、进度贴上去，我们的程序只去读公告板，不进音乐软件、也不进游戏。QQ 音乐需要在设置里手动打开这个开关。

## 2. 三个改变方案的调研结论

1. **QQ 音乐能接**。Lyricify 官方文档确认 QQ 音乐 ≥ 21.10.2962 支持 SMTC 时间轴，设置路径「设置 → 常规设置 → 通知 → 显示系统媒体传输控制」。ClearDesk 项目实测 2171.19.41.57 版本可读歌名/歌手/封面/时长，切歌与暂停成功。本机 22.61 满足。
2. **纯置顶窗在 EAC 游戏里是安全的**。反作弊监控的是游戏进程本身（注入 DLL、读内存、改存档），不管别的窗口。艾尔登法环等 EAC 游戏在无边框全屏下允许普通 always-on-top 覆盖层，与 Discord / Steam / OBS 覆盖层同类。**独占全屏会隐藏所有覆盖层**，属显示规则，改成无边框即可。按项目约定，不在带反作弊的网游里做图形层钩子或进程注入；实机截图里 Warframe 恰好在前台，只证明全局覆盖层可见，**未对它做任何部署、注入或内存读取**。
3. **歌词解析不用从零写，但必须挑对协议**：
   - QQMusicMonitor（**MIT**，Tauri 2）：SMTC + QQ 音乐 QRC 加密歌词解密 + 60fps 逐字扫光，架构可直接参考。
   - Lyricify Lyrics Helper（**Apache-2.0**，.NET）：QRC / KRC / YRC / LRC / TTML 解析、翻译、在线搜索与匹配。
   - LDDC（**GPL-3.0**）、DangoMusic（**GPL-3.0**）：**只读思路，不拷代码**，否则本项目也得被迫 GPL 开源。

## 3. 技术选型

### 决定（v1.1 修订）：Electron 45 + PowerShell 5.1 WinRT

| 层 | 技术 | 理由 |
|---|---|---|
| 宿主窗口 | **Electron 45**（Chromium） | `transparent` + `alwaysOnTop('screen-saver')` + `setIgnoreMouseEvents` 原生支持；Chromium 内容属于主窗口本身，**P0 实测真透明** |
| 媒体状态 | **PowerShell 5.1 调 WinRT `GlobalSystemMediaTransportControlsSession`** | 系统自带，零第三方依赖、零账号、零音源抓取；实测读到 QQ 音乐曲目/进度/封面 |
| UI | HTML / CSS / JS | 复用 `src/preview.html` 按 jar 规格复刻的逐字视觉，前端代码不重写 |
| 打包 | electron-builder（NSIS + portable）+ GitHub Actions | 一个安装包 + 一个绿色 exe，CI 自动出 Release |
| 配置 | `%APPDATA%\glasslyrics\config.json` | 纯本地，含开机自启开关，不上传 |

### 为什么弃用 v1.0 的 .NET 8 / WPF + WebView2

P0 实测**否决了 WebView2 宿主路线**，不是偏好问题：

1. `pywebview(WinForms) + WebView2, transparent=True` → 窗口区域呈 `[32,32,32]` 均匀深灰，WebView2 是**独立子 HWND**，父窗体底色盖住了桌面。
2. 追加 `WS_EX_LAYERED` + `#202020` 颜色键抠底 → 更糟，全部区域变 `[240,240,240]` 白底。分层合成不带子 HWND 参与，抠色键只露出父窗体白底。
3. Electron 的 Chromium 属于主窗口本身，不存在这层结构 → `transparent: true` 生效，像素判定 `P0_PASS: true`。

完整数据见 [P0验证报告.md](P0验证报告.md)。顺带 PowerShell 直读 SMTC 成功，.NET SDK 与 Python 侧车都不再需要，最终是**单语言、单 runtime**。

其余被否路线：
- **Tauri 2**：视觉和打包合适，但本机无 Rust，Windows 要补 MSVC Build Tools（数 GB）。作为二期可选迁移路线，前端可零改动带过去。
- **纯 WPF / D3D 自绘**：窗口最稳，但液态玻璃 + 辉光 + 伪 3D 要手写 HLSL，还原度与开发速度吃亏。

### 一个必须处理的技术坑

Electron 的「鼠标穿透」同样是**全有全无**：开了穿透，面板也点不了。当前解法：
- 平时（只显示歌词）→ `setIgnoreMouseEvents(true, {forward:true})`，鼠标直达游戏
- 热键唤出播放器面板 → `setIgnoreMouseEvents(false)` + `setFocusable(true)`，面板可点
- 再按热键 / `Esc` → 收起面板，恢复穿透

代价：面板唤出期间整层窗口临时不穿透。若不能接受，二期拆成「歌词窗 + 独立面板窗」双窗口。

全局热键走 `globalShortcut`（底层 `RegisterHotKey`），带候选列表自动回退，被占用不会静默失效。

## 4. 架构

```
QQ音乐 / 网易云客户端
        │  Windows SMTC（歌名·歌手·封面·进度·状态）
        ▼
[PowerShell 5.1 · smtc-bridge.ps1] ── 每 500ms 输出一行 JSON
        │  stdout 流
        ▼
[Electron 主进程 main.js] ── IPC ── 歌词引擎（P1：QRC → YRC → LRC + 缓存）
        │  globalShortcut / Tray / loginItem / config.json
        ▼
[BrowserWindow transparent + alwaysOnTop + setIgnoreMouseEvents]
        │  逐字 Glyph / DeepGlow / 左右双侧 / 中央留空
        ▼
   游戏画面（无边框全屏 / 窗口化）
```

设置（含开机自启开关）落盘到用户目录，不入库、不上传。

## 4.1 布局规范（v0.2 修订）

用户明确要求：**歌词在游戏界面中间的两边，不挡中间视野**。因此默认布局从「屏幕正中一大块」改为「左右双栏 + 中央保留区」。

| 区域 | 位置 | 内容 |
|---|---|---|
| 左栏 | `left: 3.5vw`，宽 `min(28vw, 440px)`，垂直居中 | 原文逐字歌词（主视觉）+ 上一句 / 下一句淡显 |
| 右栏 | `right: 3.5vw`，同宽，垂直居中 | 当前句翻译 + 下一句预告 + 时间 |
| 中央保留区 | 宽 `30vw`、高 `44vh`，居中 | **不放任何元素**，准星与游戏视野完全留空；预览页用虚线框标出，成品不显示标线 |
| 动态岛 | 右上角 | 避开顶部中央 HUD |
| 歌曲卡片 / 控制按钮 | 左下 / 右下 | 不进入中央区 |

1600×1000 实测：左栏右边界 496px，右栏左边界 1104px，中央保留区 560–1040px，两侧各留 64px 间隙，**矩形无重叠**（回归测试项「中央视野区与歌词不重叠」）。

可切换布局：双侧（默认）/ 居中（旧版）/ 仅左 / 仅右。所有歌词层 `pointer-events: none`。

### 已修复的三个缺陷（v0.1 → v0.2）

1. **歌词「看不见」**：并非未渲染。DOM 里 25 个逐字节点都在，但 v0.1 用 `background-clip: text` 且未高亮色仅 `rgba(...,.28)`，叠加 `drop-shadow` 后糊成灰影；整块又正压在准星上。改用**双层文字**：底层常亮 `rgba(226,238,255,.62)`，高亮层用 `::after` + `attr(data-c)` + `clip-path` 按 `--p` 裁切，纯白加发光。
2. **换曲目无效**：v0.1 的 ⏮/⏭ 只是跳时间轴，歌名和歌词不变。改为 4 首演示曲目数据，切歌同步刷新标题、封面、时长、歌词、面板高亮；面板列表可点击、搜索可过滤、进度条可拖动、播完自动下一首。
3. **中央被遮挡**：见上表布局调整，并把动态岛从顶部中央移到右上角。

回归测试：`node tools/verify_preview.mjs`（无头 Edge + CDP 真实点击读 DOM），16 项全通过。

逆向来源：jar 内**明文 GLSL 着色器**（`assets/dangomusic/shaders/`）、`javap -p` 字段/方法签名、`javap -c` 构造函数与方法字节码中的常量。只读参数，不复制任何代码（协议边界见第 5 节）。

### 映射到 Web 预览

| jar 机制 | Web 实现 |
|---|---|
| 每字独立 `Glyph` | `<span class="glyph" data-c>` 双层（主层 + 发光层） |
| `drawGlyph` 彩色 + 黑描边 | `color: rgb(247,225,215)` + `-webkit-text-stroke: .5px rgba(0,0,0,.45)` |

| `wordPop` | `--pop`：字被点亮时 `1 + .16·e^(−age/90)` 回落 |
| `wiggle` 8fps | 每 125ms 用 `hashRand` 更新每字 `--wx/--wy`（±0.8px） |
| `TextFlash.popScale` | `--slam` 按原公式每帧计算，160ms 0.28→1，附 `1.35·e^(−age/45)` 观感 |
| `DeepGlow` 多级模糊 | `.glow-layer` 同步副本 + `filter: blur(3px + radius*16px)` + `mix-blend-mode: screen`，强度映射 opacity；高亮字纯白热芯 |
| `glowTint` | `--glow-rgb` 四色可切换 |
| `fading` / `appearOf` | 上一句 0.3s 淡入淡出 |
| `splitLines` | `word-break` 自动换行 |
| `glass.frag` 边缘光 | `.glass::after` 135° 渐变 + 内外双色 inset 高光；亮度上限自适应暗化在 CSS 中不可读背景，未复刻 |

### 明确未复刻

- **`worldMode=true` 的 3D 世界空间歌词**：依赖 MC 相机矩阵、世界坐标、`facePlayer` / `keepAway` / `aboveGround` / `stayOnScreen` / `distance` / `spread`。覆盖层没有 3D 场景，无法等价实现。当前用「左右双侧布局 + 逐字发光」替代空间感，这是布局上的取舍，不是渲染参数缺失。
- **GPU 着色器本身**：Web 预览用 CSS 近似；正式版若接 WebView2 仍可考虑 WebGL 复刻 `glass.frag` / `glow/*.frag`（GLSL 可移植），但会提高显卡占用，留作二期。
- `nowPlaying` / `NotFound` / `showCover` 状态：正式版按状态展示，预览页只做静态卡片。

### 协议边界

以上均为**行为参数与算法规格的逆向观察**，用于独立实现，未拷贝 DangoMusic（GPL-3.0）任何源码。着色器文件本身也**未复制进本仓库**，只记录其算法描述。详见 `docs/第三方声明.md`。

回归测试 `node tools/verify_preview.mjs`：**29/29 通过**，含 jar 配色、描边、辉光层、非均匀时间轴、弹跳、摆动、四色切换、全部开关。

## 4.3 自捕捉游戏窗口与自适应（v0.5）

### 数据获取

`app/window-probe.ps1` 常驻，每 400ms 经 P/Invoke 读一次前台窗口，输出一行 JSON：

| 字段 | 来源 | 用途 |
|---|---|---|
| `rect` | `GetWindowRect` | **逻辑/DIP 坐标**，Electron 可直接使用 |
| `rectPhysical` | `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` | **物理像素**，去掉不可见边框；主进程除以 `scaleFactor` 后再用 |
| `process` / `title` / `className` | `GetWindowThreadProcessId` + `Get-Process` / `GetWindowTextW` / `GetClassNameW` | 游戏识别、HUD 显示 |
| `caption` / `visible` / `minimized` / `desktop` | `GWL_STYLE` / `IsWindowVisible` / `IsIconic` | 排除桌面与最小化窗口、辅助几何启发式 |

> **必须处理的坑**：PowerShell 5.1 默认非 DPI 感知，`GetWindowRect` 返回逻辑坐标，而 DWM 扩展边界返回物理坐标，本机实测相差 **1.5 倍**。直接用 DWM 值会把覆盖层甩出屏幕。实现里对 DWM 值做 `/scale`，并用 `GetWindowRect` 做 15% 容差校验兜底。

### 游戏识别（保守 + 启发式）

1. 排除桌面 / 最小化 / 自身窗口（含 `electron` 开发模式）
2. 排除明确的非游戏进程（浏览器、编辑器、音乐客户端、办公软件等）
3. 命中已知游戏进程名或标题关键字 → 视为游戏
4. 否则按**窗口占屏比例**判：`ratio ≥ 0.72`，或 `ratio ≥ 0.5` 且无标题栏 → 视为游戏（覆盖未知单机）
5. `excludeProcesses` 命中 → 跳过（**默认空**，用户自填）

### 主进程自适应

- `screen.getDisplayMatching()` 选游戏所在显示器，把窗口矩形 clamp 到屏幕内，避免溢出
- `win.setBounds()` 跟随位置/尺寸/移动/缩放；`sameBounds(±2px)` 防 400ms 轮询抖动
- 切到非游戏：`hideWhenNoGame=true` → `win.hide()`；否则回退整屏并由 renderer 淡出
- `setLayerVisible` 加状态早退，避免每轮 `show/hide` 造成闪烁与托盘菜单反复重建
- 热键 `Ctrl+Alt+F`（占用时回退 `Ctrl+Shift+Alt+F`）、托盘与面板三处都能开关

### 渲染层自适应

`window.applyAutoFit()` 按窗口宽高设 `--game-w` / `--game-h` / `--ui-scale`（`clamp(0.72, w/1707, 1.25)`）；窗口 `<1200×720` 进 `data-compact="1"`，收窄侧栏、缩字号；`body.dimmed` 处理切出淡出。中央保留区在常规与紧凑两种模式下均不含歌词元素。

### 验证

| 项 | 结果 |
|---|---|
| `node tools/verify_autofit.mjs` | **22/22 通过**（缩放上下限、紧凑模式、中央留空、勾选框、排除提示、无 JS 异常） |
| `python tools/verify_window_fit.py` | **PASS: true** |
| 实机（前台 `Warframe.x64`） | 探针逻辑 `1552×943` → 设定 `{84,47,1552,943}` → 实际 HWND 换算 `1552×943`，差 `[0,0,0,1]` px |
| HUD | 「已捕捉 Warframe.x64 · 1552×943」 |

**协议/安全**：自捕捉只读窗口几何，不打开游戏进程句柄、不读内存、不注入、不模拟按键。因此默认不排除任何游戏；此前"带反作弊网游默认排除"的旧约定已撤销，改为由用户按需填 `excludeProcesses`。

## 4.4 真实歌词引擎（P1）

### 选型结论

| 源 | 实测 | 结论 |
|---|---|---|
| **LRCLIB** `api/get` / `api/search` | 200，`syncedLyrics` 2557 字符、58 行 | ✅ 主源 |
| 网易云 `/api/search/get` | `{"code":400,"msg":"参数错误"}` | ❌ 明文搜索已失效 |
| 网易云 `/api/song/lyric/v1` | 无 Cookie 返回 `uncollected:true` | ❌ 拿不到内容 |
| QQ 音乐 QRC | 加密歌词，需 DES/XXTEA 解密 | ⏳ 二期 |

Node 内置 `fetch` 直连 LRCLIB 实测 200（不是只有 curl 能通），因此主进程直接发请求，零第三方依赖。

### 实现

`app/lyrics.js`：曲名清洗（去 `(Explicit)` / `[Remastered]` / `feat.` / 多艺人）→ `api/get` 精确匹配 → 失败退 `api/search` 按 duration 就近 → LRC 解析（多时间戳、排序、去重）→ 本地 JSON 缓存 → 返回 `{ok, source, lines:[{time,text}], synced}`。无时间轴时按行数均分。查不到回退原创演示占位。

主进程 `ensureLyrics()`：SMTC 曲目 key 变化才请求，`lyricsRequestKey` 丢弃过期结果，`lyricsInFlight` 防 500ms 轮询重复请求（初版实测连发 4 次，已修）。`lyricOffsetMs` 支持手动校准；面板「刷新歌词」强制重拉。

渲染层 `applyLyrics()`：真实行替换 `LINES`，按 SMTC `position` 二分定位当前句，行内逐字进度按 `(pos - line.time) / (next.time - line.time)` 分摊。右侧显示下一句预告。

### 诚实的限制

- LRCLIB **中文歌覆盖差**（实测中文查询返回 `[]`）。
- `hasWordSync: false` —— 只有**整行**时间轴。逐字扫光是按行时长推算的视觉近似，**不是真实逐字**。
- 真实逐字需 QQ 音乐 QRC 解密或网易云 EAPI/YRC，属二期；不为此引入 GPL 代码。

### 字形发散辉光（修复用户反馈的「方框辉光」）

### 液态玻璃主菜单

`Ctrl+Alt+P` 唤出，`#panel` 从底部小条升级为 900×580 居中面板：标题栏 + 6 项侧栏导航 + 6 个分区（播放 / 歌词 / 视觉 / 窗口 / 通用 / 关于）+ 底部热键条。玻璃层用 `backdrop-filter: blur(32px) saturate(165%) brightness(1.06)`，`::before` 做折射渐变与 RGB 色散，`::after` 做内边缘高光，近似 `ui/glass.frag` 的 SDF 圆角 + 左上主光。菜单打开时 `body[data-menu-open="1"] .side { opacity:.12 }` 让歌词淡出避免重叠。

### QQ 音乐 / 网易云音乐适配

`app/providers.js` 三个同构 provider，`app/lyrics.js` 做编排：

| 平台 | 识别 | 接口 | 结果 |
|---|---|---|---|
| QQ 音乐 | `SourceAppUserModelId` 含 `qqmusic` | `client_search_cp` → `fcg_query_lyric_new.fcg?nobase64=1` | LRC + `trans` 翻译；实测《孤勇者》54 行 |
| 网易云 | 含 `cloudmusic` / `netease` / `163` | `/api/search/get/web` → `/api/song/lyric/v1?level=ex&yv=1` + 老 `/api/song/lyric` | **YRC 真实逐字** + `tlyric`；实测 52 行 |
| LRCLIB | 兜底 | `api/get` → `api/search` | 整行 LRC |

**YRC 解析**：歌词行格式 `[行开始ms,行时长ms](字开始ms,字时长ms,0)字…`，元信息行是 JSON 对象需跳过。单次扫描 + `nextTiming()` 只把 `(数字,数字,数字)` 识别为时间括号（普通括号不误判），多字符括号均分时长，保证 `[...text].length === words.length`。输出绝对秒的 `words:[{s,e}]`，渲染层 `charMode='absolute'` 直接按 SMTC 进度算每个字的 `--p`，**不再按行时长推算**。

**质量优先**：`auto` 模式下即使前一个源已成功返回整行 LRC，仍继续尝试后面的源；一旦拿到 `wordSync:true` 立即采用，否则保留第一个可用结果。实测 QQ 音乐会话最终升级到网易云 YRC。显式指定源时立刻返回，尊重用户选择。缓存 key 含 `preferred` 与 `CACHE_VERSION='v2'`，策略升级后自动重拉一次。

**制作信息过滤**：`stripCredits` 去掉中英文制作 credit、版权、`@` 署名、intro 期的纯 ASCII 短行、以及 0–5s 的「歌名 - 艺人」标题行。修复前 QQ 音乐会显示「Vocal edite: …」当歌词。

**协议边界**：只发公开文本请求；给网易云的 `appver=3.1.39; os=pc` 是公开客户端版本标识（触发 `yrc` 返回），不是账号凭证；不保存 `MUSIC_U` / Cookie / Token。

### 本轮修掉的真 bug

1. `body.menu-open` 选择器与 `data-menu-open` 属性不匹配 → 菜单打开时歌词不淡出。
2. 菜单打开使自己的 HWND 成为前台，窗口探针判定「切出游戏」并 `resetToDisplay()`，覆盖层跳回整屏、菜单闪没 → `applyWindowFit` 检测 `cls.reason === 'self' && wasActive` 时保持已捕捉矩形。
3. 测试钩子 `GL_FORCE_LYRIC_SOURCE` 合并进 `config` 后被 `saveConfig()` **写进用户配置**，污染真实设置 → 改为 `effectiveLyricSource()` 只在使用点读取，绝不落盘。
4. QQ 音乐 LRC 制作信息被当歌词显示 → 强化 `stripCredits`。
5. `verify_window_fit.py` 曾把 `win.getBounds()` 当数组读（已在上一轮修）。
