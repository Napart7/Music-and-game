# GlassLyrics v1.4.1 · 修复「托盘菜单自己消失」与「覆盖层压住其他软件」

> 一句话：一颗每 2 秒执行的心跳，在不停地重设窗口样式。结果就是**菜单被自己关掉**，
> 其他软件的弹窗被自己压住。这版把它改成「只在真的坏了才动手」。

---

## 你报的两个现象，同一个根因

| 现象 | 触发链 | 修复 |
|---|---|---|
| 托盘图标右键 → 菜单出来，过一两秒自己消失 | ① 窗口状态一变就 `tray.setContextMenu()` 重建菜单，重建会**关闭正在显示的菜单**；② 2 秒心跳无条件重设 `setIgnoreMouseEvents` / `setFocusable`，把全屏置顶窗重新抬起并打断同进程的菜单循环 | 菜单改为**点击时按需构建**；心跳只在**检测到穿透确实失效**时才动作 |
| 打开 QQ 等软件时，覆盖层把它盖住 / 它的菜单不显示 | 同一个心跳每 2 秒把窗口重新抬到最上层；且非游戏前台时窗口仍停在 `screen-saver` 层 | 空闲期窗口调用降为 **0 次**；非游戏前台时层级降为 `floating`，系统/托盘/应用菜单永远在上 |

**实测对照**（同一台机器、同样前台窗口、覆盖层可见且已吸附）：

| | 空闲 8 秒内的窗口级调用 |
|---|---|
| 修复前 | `setIgnoreMouseEvents` × 4 + `setFocusable` × 4 |
| 修复后 | **0 + 0** |

证据文件：`docs/v1.4.1窗口抖动-修复前.json` / `docs/v1.4.1窗口抖动-修复后.json`（含计数与每次调用的归属）。

---

## 顺带修掉的三处

### 1. NVIDIA Overlay 被当成游戏
实测日志里出现过 `[fit] NVIDIA Overlay large-window` —— 显卡驱动的覆盖层是全屏大窗，
被旧启发式当成游戏吸附了，于是覆盖层贴在它上面，看起来就是"盖住了别的软件"。

- 判断逻辑抽成纯模块 `app/window-classify.js`（可单测，不再埋在 main.js 里）
- 进程黑名单 **56 → 129 项**：新增 QQ 新版（`qqnt`/`qqprotect`）、迅雷、浏览器家族、
  影音播放器、Office/Adobe、**GPU 与系统覆盖层**（`nvidia overlay`/`nvcontainer`/`gamebar`/`amdown`）、
  启动器（`steam`/`wegame`/`EpicGamesLauncher`/`Battle.net`）
- 另加正则兜底：`overlay|launcher|updater|installer|webhelper`
- 你的排除列表（「窗口」页那个输入框）依然优先，可直接写进程名

### 2. 菜单打开时会被「切出游戏时隐藏歌词」藏掉
你的配置是 `hideWhenNoGame: true`。打开主菜单时前台变成我们自己的窗口 → 判定为非游戏 →
隐藏窗口 → 菜单跟着看不见。现在**面板 / 拖动模式下永不隐藏**。

### 3. 覆盖层在有游戏时仍会抢层级
捕获到游戏窗口时才升到 `screen-saver`（为了压住无边框全屏游戏）；
其余时刻停在 `floating`，让系统菜单、托盘菜单、QQ 的右键菜单保持在上层。

## 升级

- **Windows**：`GlassLyrics Setup 1.4.1.exe`（覆盖安装，配置与位置保留）或 `GlassLyrics-Portable.exe`
- **macOS / Linux**：同版本的 dmg / AppImage / deb

升级后建议按这个顺序确认一遍：

1. 右键托盘图标 → 菜单应**一直留着**，直到你点别处或选一项
2. 打开 QQ / 浏览器 → 它们的右键菜单、下拉菜单应正常显示在覆盖层之上
3. 进游戏 → 歌词照旧吸附；切出来 → 若开了「切出游戏时隐藏歌词」，歌词应隐藏且菜单不会再被吞
