## 1. 路线变更（本轮最重要的结论）

原定：**Python + pywebview P0 原型验证 → 正式版 .NET 8 / WPF + WebView2 宿主**。
实测后否决，改为：**Electron 45 + PowerShell 5.1 WinRT 读 SMTC**。

| 尝试 | 结果 | 根因 |
|---|---|---|
| pywebview(WinForms) + WebView2，`transparent=True` | 窗口区域呈 `[32,32,32]` 均匀深灰 | WebView2 是**独立子 HWND**，WinForms 父窗体不透明；GDI 抓到的是父窗体底色 |
| 追加 `WS_EX_LAYERED` + 颜色键 `#202020` 抠底 | 更糟，全部区域变 `[240,240,240]` 白底 | 分层合成不带子 HWND 玩，抠色键只露出父窗体白底 |
| **Electron `transparent: true`** | ✅ 真透明 | Chromium 内容属于**主窗口本身**，不存在独立子 HWND |

顺带两个收获：
- **PowerShell 5.1 直接读 WinRT SMTC 成功**，零第三方依赖。因此不再需要 .NET SDK、不再需要 Python 侧车，单 runtime 打包。
- npm 的 Electron 二进制默认从 GitHub 下载会被墙，已用 `https://npmmirror.com/mirrors/electron/` 镜像解决，并写进 `app/.npmrc` 与 CI。

## 5. P0.5：自捕捉游戏窗口与自适应（通过）

用户补充要求「会自捕捉游戏窗口做自适应」。实现见 `docs/技术方案.md` 第 4.3 节。

- 新增 `app/window-probe.ps1`：P/Invoke 读前台窗口，输出逻辑矩形、物理 DWM 矩形、进程名、标题、类名、窗口样式。
- **踩坑**：`GetWindowRect` 是 DPI 虚拟化后的逻辑坐标，`DwmGetWindowAttribute` 是物理坐标，本机差 1.5 倍。主进程对 DWM 值除以 `scaleFactor`，并用 `GetWindowRect` 做容差兜底。
- **踩坑**：初版默认把 Warframe 放进 `excludeProcesses`，导致用户屏幕上自适应根本没激活。自捕捉只读窗口几何、不碰进程，安全边界在"不注入不读内存"，默认排除是错的 → 改为默认空列表。
- 实机验证（`docs/自适应自检.json`）：前台 `Warframe.x64`，`active: true`、`ratio 0.804`、逻辑矩形 `[84,47,1552,943]`；`win.getBounds()` 为 `{84,47,1552,944}`；Python 读实际 HWND 换算回逻辑为 `[84,47,1552,943]`。
- `python tools/verify_window_fit.py` → **PASS: true**（设定矩形 vs 实际窗口差 `[0,0,0,1]` px；探针 vs 实际差 `[6,0,12,6]` px）。
- `node tools/verify_autofit.mjs` → **22/22 通过**。
- 截图 `docs/自适应实机截图-预览.png`：歌词与状态胶囊只在游戏窗口区域内，桌面侧边与顶部任务栏无溢出，中央角色未被遮挡。

### 接口探测先于编码

| 接口 | 结果 |

| 网易云 `/api/search/get/web` | 通（上一轮测的 `/api/search/get?type=1` 才是 400） |

| 网易云老 `/api/song/lyric?lv=1&kv=1&tv=-1` | 通，LRC + `tlyric` |
